# GAM EDU — Repository Agent Instructions

Before modifying student-enrichment modules (`narrated-lessons`, `coding-club`, `boolean-logic`, `sql-practice`, `python-runner`, `pseudocode-runner`) or publishing lessons:

1. **Read and follow** [`docs/STUDENT_ENRICHMENT_STANDARD.md`](docs/STUDENT_ENRICHMENT_STANDARD.md).
2. **Protect core school management routes**: Never import student-enrichment engines into core school management modules (`finance`, `financials`, `accounts`, `attendance`, `admin`, `students`, `staff`, `dashboard/layout.tsx`).
3. **Keep content CDN-first**: Never commit lesson JSONs or teacher solution packs to git; publish approved lessons via `scripts/lessons/publish-lesson.ts`.
4. **No new lesson-specific React components** or hardcoded `lessonId` branches in `NarratedLessonPlayer.tsx` without explicit architectural approval.
5. **Security & Tests**: Run `npx vitest run src/lib/narrated-lessons/svg-sanitizer.test.ts src/lib/narrated-lessons/architecture-boundaries.test.ts` after any narrated-lesson or sanitizer change.
6. **Manual Vercel Production Promotion Policy**: Production deployment is strictly manual in Vercel. A successful Git push to `origin/fixed-version` or a "Ready" Vercel preview build does **not** establish that a revision is live in production. Always verify live behaviour on `https://gam-it-service.app` after explicit manual promotion before certifying a release as live.
7. **Owner's Revised Student Enrichment Development & Under-Construction Policy**: The owner has authorised accelerated development and controlled `fixed-version` integration of approved Student Enrichment foundation capabilities (Steps 5A.1 → 6) and real NaCCA/Cambridge curriculum lessons while Student Enrichment remains **Under Construction** (`src/lib/student-enrichment-release.ts`). Ordinary student access MUST remain restricted until the owner's explicit release approval (`NEXT_PUBLIC_STUDENT_ENRICHMENT_RELEASED=true`). Core school-management functionality remains strictly protected and unaffected.
8. **Step 5H Creative & Computational Audit Reference**: Follow [`docs/STEP_5H_CREATIVE_COMPUTATIONAL_AUDIT.md`](docs/STEP_5H_CREATIVE_COMPUTATIONAL_AUDIT.md) as the permanent planning reference for future Step 5H (Visual Programming Studio, bounded Art Studio, and Game Zone integration). Do **not** commence Step 5H before completing Steps 5A–5G; however, investigate any confirmed high-severity security risks promptly without deferring active vulnerabilities.

9. **Agent Roles & Coordination (owner-established, permanent):** Gemini is the Primary Developer (new engines, capabilities, curriculum lessons, the approved roadmap); Claude is the Independent Auditor and Corrective Engineer (reviews Gemini's work, verifies independently, fixes confirmed defects, strengthens security, runs regression tests, pushes verified corrections to `fixed-version`); ChatGPT is the Technical Coordinator; the owner has final authority (manual Vercel promotion, official student release, expenditure, major architectural decisions). Follow [`docs/AGENT_COORDINATION_PROTOCOL.md`](docs/AGENT_COORDINATION_PROTOCOL.md). Keep separate progress records (`docs/GEMINI_DEVELOPMENT_PROGRESS.md`, `docs/CLAUDE_AUDIT_PROGRESS.md`), classify every finding as `CLAUDE_FIX`, `GEMINI_BUILD`, `JOINT_REVIEW`, `OWNER_DECISION` or `VERIFICATION_REQUIRED` in `docs/CONSOLIDATED_DEFECT_REGISTER.csv`, and read `docs/FOUNDATION_MASTER_STATUS.md` before starting. Claude does not start Gemini's development stages (5F, 5G, 5H, Step 6); Gemini does not weaken audit fixes without a `JOINT_REVIEW`.
10. **Permanent engineering gates from the independent audit:** (a) learner-written code (Python and any future language) MUST run only in an isolated opaque-origin sandbox with a restrictive CSP and validated messaging (`src/lib/python-runner.ts`); never execute it in the application origin, never expose cookies, IndexedDB, Cache Storage or authenticated endpoints to it; (b) AI and credit-spending API routes MUST authenticate, authorise (school membership + role, release restriction mirrored on the server), bound request size, and use a shared Firestore-backed cap that fails closed (`src/lib/ask-teacher-guard.ts`); (c) `.github/workflows/foundation-verification.yml` must stay green on `fixed-version` (lockfile sync via `npm ci`, enrichment and security tests, independent math oracle, TypeScript ratchet, emulator rules tests).
