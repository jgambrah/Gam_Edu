# Narrated Lessons — Audio & Human Re-Recording Workflow

## How `audioSource` Works

Every slide in `src/lib/narrated-lessons/bs7-sci-t1-water-cycle.json` has an `audioSource` field on its `narration` object:

- `"tts"` (default): Audio is generated by Gemini TTS (`Kore`) from `narration.ttsText` (built automatically from `narration.script` + `pronunciationGuide`).
- `"human"`: Audio was recorded by a Ghanaian teacher or staff member. The TTS generator (`scripts/lessons/publish-water-cycle-media.ts`) **always skips** slides with `audioSource: "human"` and will never overwrite them.

## How to Upload and Attach a Teacher's Recording to a Single Slide

1. **Record the slide narration** in a quiet room (phone voice memo, `.m4a`, `.wav`, or `.mp3`), reading the slide's on-screen `narration.script` verbatim (do **not** read phonetic respellings).
2. **Run the attach command** from the repository root:
   ```bash
   npx tsx scripts/lessons/publish-water-cycle-media.ts --attach-human s07 "C:\path\to\teacher-s07-recording.m4a"
   ```
3. **What the command does automatically:**
   - Transcodes and normalizes the recording via `ffmpeg` to `64 kbps` mono MP3 (`audio/s07.mp3`) so file size matches the rest of the lesson (~350–450 KB for low-end phones).
   - Uploads the MP3 directly to Firebase Storage CDN at `story-spark-preview/narrated-lessons/bs7-sci-t1-water-cycle/audio/s07.mp3` and verifies `HTTP 200 OK`.
   - Updates `slides[s07].narration.audioSource` to `"human"` in `src/lib/narrated-lessons/bs7-sci-t1-water-cycle.json` so future TTS regeneration runs permanently skip `s07`.
4. **Commit the updated JSON** so the `"human"` protection flag is persisted in Git.

## Reverting a Slide Back to TTS

If you later want TTS to manage that slide again, change `slides[s07].narration.audioSource` back to `"tts"` in the lesson JSON and run:
```bash
npx tsx scripts/lessons/publish-water-cycle-media.ts --audio-only
npx tsx scripts/lessons/publish-water-cycle-media.ts --upload-only
```
Because each slide is cached by the SHA-256 hash of its `ttsText`, only slides whose `ttsText` changed (or whose `.mp3` / `.sha256` is missing) will be regenerated.
